## 1. Methodological Objective

This document formalizes the pre-registered experimental protocol governing the comparative evaluation of traffic signal controllers in Eclipse SUMO. The protocol is designed to eliminate methodological vulnerabilities prevalent in transportation simulation literature, specifically:
1. **Pseudoreplication**: Conflating micro-level vehicle observations with independent experimental replications.
2. **Boundary Warm-up Contamination**: Distorting delay metrics with vehicles that entered the network prior to steady-state signal operation.
3. **Straw-Man Comparisons**: Evaluating adaptive algorithms against uncalibrated, excessively long static cycle baselines without benchmarking against well-calibrated fixed-time plans (e.g., Webster's optimum formulation).
4. **Data Dredging & Cherry-Picking**: Selecting favorable seeds or scenarios post-hoc.

## 2. Experimental Unit & Sample Size

### 2.1 Formal Definition of Experimental Unit
The experimental unit is the **matched simulation realization**:
$$\mathcal{E} = (\text{scenario } s, \text{ seed } k)$$
where $s \in \{\text{low, medium, high, oversaturated, asym\_ns, asym\_ew, dynamic}\}$ and $k \in \{42, 43, 44, 45, 46\}$.

- **Number of Independent Replications**: $N = 5$ independent stochastic realizations per scenario.
- **Matched-Pairs Pairing**: For each realization $(s, k)$, all four controllers evaluate the **exact same immutable route demand file**. Controller performance is compared via paired differences:
  $$D_{s, k} = Y_{\text{candidate}, s, k} - Y_{\text{comparator}, s, k}$$
  Pairing cancels out inter-seed stochastic variation (e.g., vehicle arrival burstiness), isolating the net treatment effect of the control algorithm.

### 2.2 Rejection of Vehicle-Level Independence
Treating individual simulated vehicles as independent experimental observations is statistically invalid due to:
- **Spatial-Temporal Coupling**: A vehicle stopped at a red signal directly delays following vehicles through shockwave propagation.
- **Shared Signal State**: All vehicles in a run experience the identical signal phase sequence generated by the controller during that run.
- **Statistical Distortion**: Pooling 200–500 vehicles within a single run artificially deflates standard errors by $\sqrt{N_{\text{veh}}} \approx 15\text{--}25$, manufacturing false statistical significance ($p < 10^{-10}$).

## 3. Vehicle Cohort Isolation Standard

To prevent boundary warm-up effects from biasing network performance metrics, vehicles are classified into three mutually exclusive cohorts based on their departure time ($t_{\text{depart}}$) and arrival time ($t_{\text{arrive}}$) relative to the $200\,\text{s}$ warm-up threshold:

$$\text{Simulation Duration } T = 1000\,\text{s}, \quad \text{Warm-Up Window } T_{\text{warm}} = 200\,\text{s}$$

1. **Cohort A (Pure Evaluation Population — PRIMARY AUDIT STANDARD)**:
   $$\text{Cohort A} = \{v \in \mathcal{V} \mid t_{\text{depart}}(v) \ge 200\,\text{s} \land t_{\text{arrive}}(v) \ge 200\,\text{s}\}$$
   - These vehicles departed into a fully established, dynamic traffic network and completed their trip before simulation conclusion.
   - **All primary and secondary evaluation metrics in this research are computed exclusively on Cohort A.**
2. **Cohort B (Boundary Crossing Population)**:
   $$\text{Cohort B} = \{v \in \mathcal{V} \mid t_{\text{depart}}(v) < 200\,\text{s} \land t_{\text{arrive}}(v) \ge 200\,\text{s}\}$$
   - Vehicles that departed into an empty network during initial warm-up but finished after warm-up. Excluded from primary metrics.
3. **Cohort C (Pure Warm-Up Population)**:
   $$\text{Cohort C} = \{v \in \mathcal{V} \mid t_{\text{depart}}(v) < 200\,\text{s} \land t_{\text{arrive}}(v) < 200\,\text{s}\}$$
   - Vehicles that both entered and cleared the network during warm-up. Strictly quarantined.

## 5. Baseline Controller Descriptions

To ensure an unbiased and rigorous benchmark, the proposed controller is compared against three distinct operational strategies:

1. **C0 — Original Uncalibrated Fixed-Time Controller (`FixedTimeSignalController`)**:
   - Represents unoptimized legacy pre-timed control.
   - Cycle: $90\,\text{s}$ (Phase 0: NS Green 42s, Phase 1: NS Yellow 3s, Phase 2: EW Green 42s, Phase 3: EW Yellow 3s).
2. **C1 — Webster-Calibrated Minimum-Cycle Fixed-Time Controller (`OptimizedFixedTimeSignalController`)**:
   - Represents a mathematically calibrated fixed-time timing plan derived from Webster's optimum cycle formula:
     $$C_0 = \frac{1.5 L + 5}{1 - Y}$$
   - Subject to driver safety constraint $G_{\text{min}} \ge 15\,\text{s}$, yielding an optimal $36\,\text{s}$ cycle (Phase 0: NS Green 15s, Phase 1: NS Yellow 3s, Phase 2: EW Green 15s, Phase 3: EW Yellow 3s).
3. **C2 — Basic Queue-Based Adaptive Controller (`BasicDensityController`)**:
   - Represents naive real-time queue allocation without damping.
   - Compares instantaneous queue totals: $Q_{\text{NS}}$ vs $Q_{\text{EW}}$.
   - Switches immediately when opposing queue is larger, constrained only by $G_{\text{min}} = 15\,\text{s}, G_{\text{max}} = 50\,\text{s}, Y = 3\,\text{s}$, and starvation ceiling $R_{\text{starve}} = 45\,\text{s}$.
4. **C3 — Proposed Composite Adaptive Controller (`ProposedAdaptiveSignalController`)**:
   - Multi-factor formulation integrating queue ($Q$), arrival pressure ($A$), queue growth ($G$), waiting burden ($W$), continuous red aging ($R$), and switching hysteresis ($H = 0.20$).

## 6. Recorded Performance Metrics

At the conclusion of each simulation run, the following metrics are extracted from Cohort A vehicles:
- **`mean_waiting_time_s` (Primary Endpoint)**: Average accumulated time (in seconds) that vehicles spent at velocity $v < 0.1\,\text{m/s}$.
- **`mean_travel_time_s`**: Average total trip duration from departure to arrival in seconds.
- **`mean_delay_s`**: Average time-loss delay relative to theoretical free-flow travel time ($L / v_{\text{max}}$).
- **`mean_queue_veh`**: Time-average total queue length across all four incoming approaches.
- **`throughput_cohort_a`**: Count of Cohort A vehicles that successfully completed their trip.
- **`phase_switch_count`**: Total number of signal phase transitions executed during the simulation run.

## 7. Confirmatory Inferential Testing Protocol

1. **Family Definition**: The confirmatory family is strictly restricted to the **21 primary tests** on Cohort A mean waiting time (7 scenarios $\times$ 3 comparator contrasts).
2. **Parametric Test**: Two-sided paired Student's $t$-test ($df = N - 1 = 4$).
3. **Non-Parametric Test**: Two-sided exact Wilcoxon signed-rank test (serves as an ordinal check; note that with $N=5$, $p_{\text{min}} = 0.0625$).
4. **Standardized Effect Size**: Paired Cohen's $d_z = \bar{D} / s_D$.
5. **Multiple Testing Adjustments**:
   - Holm-Bonferroni step-down procedure (FWER $\le 0.05$).
   - Benjamini-Hochberg step-up procedure (FDR $q \le 0.05$).
6. **Secondary Outcomes**: All secondary metrics are explicitly labeled **exploratory** and analyzed independently from the primary family.
